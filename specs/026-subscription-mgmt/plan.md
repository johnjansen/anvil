## Summary

Add CLI commands to manage task subscriptions: list all subscriptions, pause/resume individual subscriptions, and view subscription details. This builds on the existing subscription infrastructure (filesystem and message queue subscriptions) by adding operational control commands.

**Project Type**: CLI tool
**Performance Goals**: List subscriptions <2s; pause/resume <1s
**Constraints**: Must work with existing subscription types (fs, amqp); state persisted across daemon restarts

## Phase 1: Design

### Data Model

**New Types**:

```go
// SubscriptionStatus represents the state of a subscription
type SubscriptionStatus string

const (
    SubscriptionStatusActive  SubscriptionStatus = "active"
    SubscriptionStatusPaused  SubscriptionStatus = "paused"
)

// SubscriptionState represents the runtime state of a subscription
type SubscriptionState struct {
    TaskID    string            `json:"task_id"`
    Type      string            `json:"type"`       // "fs", "amqp", etc.
    Status    SubscriptionStatus `json:"status"`
    TaskName  string            `json:"task_name"`
    CreatedAt time.Time         `json:"created_at"`
    TriggerCount int64          `json:"trigger_count"`
    // Type-specific config (fs, amqp, etc.)
    Config    json.RawMessage   `json:"config"`
}
```

**Existing Types Used**:
- FileSubscription (from filesystem subscription)
- MessageSubscription (from message queue subscription)
- Todo (task configuration)

### CLI Commands

```
anvil subscription ls              # List all subscriptions
anvil subscription ls --json      # JSON output
anvil subscription pause <id>     # Pause a subscription
anvil subscription resume <id>    # Resume a subscription
anvil subscription info <id>      # Show subscription details
anvil subscription info <id> --json  # JSON output
```

### Storage

Subscription state stored in `.anvil/subscriptions/state/<task-id>.json`:

```json
{
    "task_id": "task-123",
    "type": "fs",
    "status": "active",
    "task_name": "process-data",
    "created_at": "2026-03-01T10:00:00Z",
    "trigger_count": 42
}
```

### Daemon Interface

CLI communicates with daemon via Unix socket:
- `subscription list` → daemon returns all subscription states
- `subscription pause <id>` → daemon updates status to "paused"
- `subscription resume <id>` → daemon updates status to "active"
- Daemon reads status on startup and restores state

## Edge Cases Handled

1. **Daemon not running**: CLI returns error indicating daemon unavailable
2. **No subscriptions**: Empty list with helpful message
3. **Invalid subscription ID**: Clear error message
4. **Pause already paused**: Success, no-op
5. **Resume already active**: Success, no-op
6. **Daemon restart**: Paused subscriptions maintain state
